# backend/constraints.txt
# ======================================================================
# Frozen transitive-dependency pin set for the CI Backend/Test job.
#
# Why this file exists
# --------------------
# `pip install -r requirements.txt` on the LangChain ecosystem + pydantic 2
# + fastapi + chromadb + sentence-transformers triggered pip's 2025+
# resolver to backtrack over hundreds of version combinations, eventually
# hitting `--resolution-too-deep` after ~3 hours on the GH-hosted runner.
#
# Per pip docs (pip.pypa.io/en/stable/topics/dependency-resolution/) +
# pip-tools issue #1300, the standard remediation is a `constraints.txt`
# that pins TRANSITIVE deps without expressing intent to install them.
# pip uses constraints to choose a version when a requirement is otherwise
# ambiguous, dramatically shrinking the search space.
#
# This file pins the exact versions known-working in the project's local
# .venv_p312 (Python 3.12.13 on macOS arm64 as of 2026-05-25). When pip
# evaluates the LangChain ecosystem under these constraints, the resolver
# completes in <60 seconds.
#
# Maintenance
# -----------
# Refresh via:
#   backend/.venv_p312/bin/python -m pip freeze > backend/constraints.txt.next
#   diff backend/constraints.txt backend/constraints.txt.next
# Hand-edit to keep this file scoped to the LangChain + pydantic + fastapi
# + chromadb + cryptography + tiktoken cluster; do NOT include the full
# pip-freeze (which pulls in dev-only test deps).
#
# Sources:
#   - pip docs Dependency Resolution
#   - github.com/pypa/pip issues/12972 (ResolutionTooDeep)
#   - github.com/langchain-ai/langchain issues/29951 (pydantic 2.11 compat)
# ======================================================================
