## 5. Design specs — the three high-impact primitives

### 5.a — BBS+ selective-disclosure proofs for PII-safe token exchange

**Closes:** Cluster B.3 + C-3 BBS+ ceilings (deepens F4). **Replaces:**
O3's in-process `ReleaseContext` with a cryptographic, auditor-verifiable
release.

**Standard:** W3C Data Integrity BBS cryptosuite (`vc-di-bbs`), BLS12-381,
3-operation model.

```
Issuer (vOS attestation service, Trust Domain A):
    base_proof = BBS.Sign(sk, [mandatory_stmts || selective_stmts])
    # mandatory: schema/@type, tenant trust-domain, attestation epoch
    # selective: each PII field as its own canonicalized N-Quad statement
Holder (the agent / federation bridge):
    derived = BBS.ProofGen(pk, base_proof,
                           reveal = {cleared_pii_kinds},
                           pseudonym = verifier_scoped_nym)   # unlinkable
Verifier (vOS instance, Trust Domain B):
    ok = BBS.ProofVerify(pk, derived, revealed_stmts)
    # learns ONLY the cleared kinds; cannot link across verifiers
```

**Enforcement contract (`require_bbs_release`):** an outbound PII send is
permitted iff the payload's PII kinds ⊆ the kinds proven by a **valid,
unexpired BBS derived proof** bound to *this* destination's trust domain.
On a missing/invalid/over-broad proof → `OutboundPiiBlocked` (fail-closed,
reusing O3's exception). This upgrades `ReleaseContext.reviewed=True` from
a Python boolean a bug could forge into a proof an auditor can verify.

**Mechanics to implement:** RDF canonicalization → N-Quads; HMAC
blank-node shuffle (anti-correlation); mandatory-pointer set; CBOR proof
serialization; **anonymous holder binding** (so a stolen base proof can't
mint derived proofs); **credential-bound pseudonyms** (verifier-scoped,
cross-verifier-unlinkable).

**Honest scope ceiling:** depends on a constant-time BBS lib (the B.1
ceiling already flagged this). Ship behind `VOS3_BBS_BACKEND={blst|stub}`;
the `stub` path is test-only and logs LOUD. Groth16 DV-SNARK
"bytes-match-policy" proofs remain Sprint 23+.

**Tests:** reveal-subset correctness; over-broad-reveal rejection;
cross-verifier unlinkability; expired-proof rejection; holder-binding
forgery rejection; O3 integration (PII to untrusted dest allowed *only*
with a valid derived proof).

### 5.b — Verifier-clean eBPF loop over the byte-level `colors[]` array

**Closes:** C3 (deepens C7). **Problem today:** the per-byte `bpf_loop`
scan in `kernel/src/sec/taint_gate.c` is bounded at 4096 bytes; larger
toxic buffers fall back to blob-level. We want a **verifier-clean**,
performance-optimized scan that the kernel's eBPF verifier accepts with
no unbounded-loop rejection, over arbitrarily large `colors[]`.

**Design — the "loop dance":**
```
// colors[]: one byte label per content byte (PUBLIC/UNTRUSTED/SECRET/TOXIC)
// Goal: find the first byte whose label exceeds the sink-policy ceiling,
//       across a buffer larger than the 4096 bpf_loop cap, while keeping
//       the verifier happy (every memory access provably in-bounds).

1. CHUNK: outer bpf_loop(N_CHUNKS, scan_chunk, ctx, 0)
          where N_CHUNKS = ceil(len / CHUNK)  // compile-time-bounded constant
2. scan_chunk(idx, ctx):
       base  = idx * CHUNK
       // verifier needs a CONSTANT bound + an explicit mask:
       #pragma unroll
       for (u32 i = 0; i < CHUNK; i++) {     // CHUNK = 256, unrolled
           u32 off = (base + i) & COLORS_MASK; // mask proves in-bounds
           if (off >= ctx->len) return 0;      // ragged-tail guard
           if (colors[off] > ctx->ceiling) {   // toxic span hit
               ctx->deny_off = off; return 1;  // early-exit the outer loop
           }
       }
       return 0;
3. On deny_off set within the write's [start,limit): return -EPERM.
   A clean prefix (colors[start..deny_off] all <= ceiling) is allowed
   through; the TOXIC region of the SAME buffer is refused (EchoLeak).
```

**Why verifier-clean:** (1) outer loop count is a *constant* (`N_CHUNKS`
derived from a bounded max buffer, 1 MiB → 4096 chunks); (2) inner loop
is `#pragma unroll`ed with a constant `CHUNK`; (3) every `colors[]` access
is masked (`& COLORS_MASK`) **and** length-guarded — the verifier proves
in-bounds without a runtime-variable bound it would reject.

**Performance:** masked + unrolled inner scan vectorizes; early-exit on
first toxic byte means clean traffic pays ~O(prefix), not O(len).
Per-byte mode stays opt-in (`TaintMode.PER_BYTE`) — blob-level remains
the default for non-sensitive sinks.

**Enforcement contract:** unchanged from C7 (`socket_sendmsg` /
`file_permission` LSM hooks return `-EPERM`), now over unbounded buffers.

**Honest ceiling:** still requires the Linux ≥ 5.17 + `bpftool` load
(the standing GA gate); on macOS dev the connector stays MOCK and logs.
Validated only on a Linux runner.

**Tests:** clean-prefix-allowed / toxic-tail-denied at 64 KiB / 1 MiB;
verifier-load success on a Linux CI runner (skipif-gated); early-exit
latency benchmark vs blob-level.

### 5.c — Hardware-enforced fail-closed GPU allocation validator

**Closes:** O4 (NEW row); shares enforcement with E4/E7/O2 (the
`enforced-pending-silicon` hardware items). **The original "O3
noisy-neighbor admission gate" idea, done as real admission control.**

**Enforcement contract (`require_isolated_gpu_alloc`):** an agent is
granted accelerator memory on a *shared* host iff ALL hold, else
`GpuAllocRefused` (fail-closed):
```
1. MIG partition present  — /proc/driver/nvidia/.../mig_mode == 1
                            AND the target instance is a distinct MIG UUID
2. Confidential Compute on — GPU CC mode == ENABLED (Blackwell/Hopper)
3. Fresh attestation       — a NVIDIA attestation quote (same SDK as
                            single-GPU) verified < ATTEST_TTL old, bound
                            to the MIG instance UUID
4. cgroup resource caps    — the agent's cgroup has memory + SM limits
                            matching the NVIDIA reference (no overcommit)
```

**Composition with existing gates:** runs *after* E3 (IOMMU enforcing)
and *before* the `model_manager.load_to_kernel()` warp — so the bind
order is **E3 (no DMA bypass) → 5.c (isolated partition) → E6 (perf
counters locked) → warp**. All four are fail-closed; any refusal aborts
the bind before accelerator memory is handed over.

**Today (no Blackwell on the dev host):** the validator reads host
state read-only and **fail-closes on an unverifiable host** unless
`VOS3_GPU_ALLOC_DEV_OVERRIDE=1` (loud WARNING) — identical to the
E3/E6 dev-override pattern. A `mig_isolation_sim` modeled stub backs the
unit tests; real validation is a Blackwell customer-pilot gate (2027).

**Honest accounting:** O4 flips to `vOS-ENFORCED` (new row) when the
software validator ships **and** is proven on real Blackwell silicon at a
pilot. Until then it is `enforced-pending-silicon` like its E4/E7
siblings — software gate live, silicon validation pending.

**Tests:** refuse-on-missing-MIG; refuse-on-CC-off; refuse-on-stale-quote;
refuse-on-overcommitted-cgroup; allow-on-all-four (injected fake
procfs/sysfs, like the E3/E6 suites); dev-override path.
