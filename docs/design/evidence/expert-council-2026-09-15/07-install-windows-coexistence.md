# Persistent installation and Windows coexistence

Reviewer: `/root/rust_upgrade` (one actual agent, architecture/build/hardware council track). Source baseline: `32187957757ab57d7820d0a63fa62c409003b126`. These are seven specialized reviews by one reviewer, not seven independent agents.

**P1 — Persistent installation remains a release gate.** [README.md](../../../../README.md) distinguishes bootable ISO packaging from installation. The keyboard wizard smoke demonstrates UI flow in a disposable VM, not safe partition changes, durable installed state, recovery or upgrades. Before a production installer, require a disposable-disk matrix covering blank/existing disks, reboot persistence, interrupted installation and recovery. Never treat a final wizard screen as proof of a committed disk installation.

**P1 — Define and qualify each Windows mode separately.** CORE-02 in [docs/design/CORE_REQUIREMENTS.md](../../../../docs/design/CORE_REQUIREMENTS.md) treats coexistence as a requirement. Dual boot, Windows-hosted virtualization/transport and a hosted desktop shell have different trust and deployment boundaries. [consolidation/reconciliation/FEATURE_DECISIONS.md](../../../../consolidation/reconciliation/FEATURE_DECISIONS.md) explicitly rejects donor Hyper-V loopback/default-success transport and nonworking VBS scaffolds as implementations. Choose the first supported mode and test its actual boot/transport/authentication behavior, reconnects and failure paths; do not use one mode's evidence to claim the others.

**P2 — Correct operator documentation before exposing destructive workflows.** The legacy GRUB instructions in [docs/DEPLOYMENT.md](../../../../docs/DEPLOYMENT.md) do not match current Limine packaging. Update and rehearse the concrete supported procedure while preserving existing user data in coexistence tests. Reviewed requirements, packaging and reconciliation decisions; no Windows host, partition operation or physical installation was executed.
