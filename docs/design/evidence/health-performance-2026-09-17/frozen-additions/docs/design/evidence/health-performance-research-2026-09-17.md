## Local hypothesis and acceptance conditions

The preserved health ELF is unchanged, but its producer calls GETTIME for every push-loop iteration. Counters should separate syscall entry/exit, handler time, signal checks, deferred work, CPU-ID queries, root synchronization, CR3 writes and actual reschedules. Prefer aggregated counters outside the measured loop; per-call logging would distort the workload. Compare identical instrumentation in old/current kernels with the same emulator, firmware, memory, workload order and isolated run conditions. Preserve failed samples and distinguish guest time from host elapsed time.

The candidate in `kernel/src/arch/x86_64/kpti_roots.c` is **compare-before-store of the same desired PML4 values**. It remains a hypothesis under review, not a diagnosed cause or validated improvement. Every entry must still be checked: entries 0–255, 256 and 511 copy the full root; all other entries become zero. Preserve null/overlap validation, existing AS locking, root binding and CR3/flush behavior. Explicit atomic/volatile accesses and generated-code inspection must establish that redundant stores really disappear. Compare every bit, including Accessed; do not mask permission or hardware-bit differences to manufacture equality. Existing hardware-update and nonparticipating-writer concurrency limits remain.

Qualification requires actual-source equivalence tests for arbitrary roots, mapping removal and permission changes, A-bit differences, unchanged roots, and rejected overlapping storage. Native isolation/translation regressions must remain effective. Measure the proposed optimization separately from CPU-ID caching or any other change so attribution remains possible.

**The 80,000 messages/s threshold, duration, messages and correctness checks remain unchanged.** Keep user MMIO denied, preserve ownership/refcount rules, user/kernel permissions, register isolation, root switching and TLB acknowledgement. Do not bypass signal delivery or resource cleanup for GETTIME. A narrower empty-work fast path needs synchronized state and a proof that pending work cannot be lost. No physical-hardware, full-SMP, cancellation-safety or release qualification follows from these discussions.
