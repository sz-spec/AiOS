# External AI-context callers: bounded ownership conversion

Author: `/root/mcp_upgrade`. These are implementation notes, not independent approval of this author's changes.

Telemetry now acquires a global context reference and puts it on snapshot success, short-buffer rejection and ioctl statistics completion before user copy. APPLIST acquires/puts each context. Dispatcher KILL_ALL removes the redundant borrowed existence check and relies on the scrub operation to own its lookup. Task destruction/reaping clears `ai_guard_ctx` before releasing its retained reference with `ctx_put`; it no longer closes the registry's context.

APPLOAD returns explicit ENOTSUP before performing any allocation, context creation, task creation or publication. The removed implementation passed a stack request to a child, signaled completion before its last use of that request, timed out without owning child lifetime, and never enqueued the task returned by `vos3_task_create`. That factory publishes a READY task in the task table before returning; it is not an unpublished-task factory. Disabling this unsafe/nonfunctional launcher is an explicit capability restriction, not a successful app launch. Reopening requires an unpublished owned-task factory, explicit scheduler enqueue, lifetime-safe startup/request/reaping, and authenticated administrator authorization. Other bridge command interfaces remain present.

`scripts/test_ai_context_external_callers.py` compiles the actual APPLOAD function against only its error sink and checks explicit unsupported responses for valid, absent and truncated-looking IDs. Allocation/task/context/scheduler dependencies have no linked implementations, so they cannot silently run in this test. The actual telemetry snapshot is compiled against simplified data-layout fixtures and controlled acquire/put functions; success, short buffer, empty context and one-region output all conserve references. This is not a production ABI/layout or concurrent-region test. Four tests passed in 1.127 seconds. Additional actual-source syscall tests reject full-width IDs 8, 263 and UINT64_MAX before core dispatch for create/destroy/switch, while ID 7 dispatches unchanged. A preservation regression verifies APPSTAT, APPKILL, APPLOGS and AGENT_KILL_ALL against frozen SHA-256 function fixtures from baseline f8c0b82 and APPLIST against only its intended pin conversion. An initial overbroad APPLOAD replacement accidentally removed adjacent commands; independent review caught this, the commands were restored, and the preservation test prevents recurrence.

Remaining boundaries: context pins do not serialize mutation/free of individual region nodes. Telemetry and fault handling need a separate region snapshot/locking contract. APPKILL/dispatcher task-table lookup, remote stopping and repeated defer operations are not solved by context references. Syscall full-width ID validation and core registry synchronization are owned by the coordinator. No QEMU or kernel build was run for this step.


Independent core review (coordinator-authored implementation): registry lookup and retain share the IRQ-safe registry lock; close detaches every published alias before consuming its owner; a failed competing publication closes its unpublished candidate. Last puts enqueue without inline region destruction. The reaper detaches the retired list under lock and frees outside it only with saved IF enabled and a current task. Internal integrity/reprotect/reclaim/status/access-check/scrub paths inspected conserve context pins, including cross-app denial. This is conditional source approval only for retained-reader and reaper continuations that complete normally. It is not approval of cancellation-safe context lifetime, individual region lifetime or concurrent allocation/free safety. Ordinary allocations use kernel high-half addresses and VMM selects the kernel address space for those addresses, so arbitrary reaper-task AS does not itself establish a wrong-AS defect for that allocation path. Nested interrupts that explicitly enable IF, huge/shared backing finalization and actual populated-context native teardown are not qualified by the four caller tests.

Authorization remains separate: full-width app-ID checks prevent truncation aliases but do not establish creator/admin permission for valid-ID create/destroy/switch. Global active-app state also remains outside a per-principal authority model. APPLOAD stays unavailable pending the documented safe startup and administrator authorization contract.


Cancellation findings remain release blockers (read-only review, 2026-09-17). They are reachable on a single CPU; no SMP proof is needed for this interleaving:

- `ai_telemetry.c:227–239` acquires a transient context reference into a kernel-stack local. Timer IRQ rescheduling at `interrupts.c:849–873` has no interrupted-CPL restriction. Another task can invoke APPKILL, which calls `vos3_task_kill`; `task.c:1198–1203` marks the reader terminal and removes it without unwinding its continuation. Final task cleanup handles the single wait-cleanup record and persistent `task->ai_guard_ctx`, not these transient pins. The orphaned reference prevents final reclamation after close.
- `ai_guard.c:757–765` detaches an entire retired list into a stack local before reclaiming with interrupts enabled. Abandoning that reaper continuation can lose the remaining zero-reference objects. A transient-pin ledger alone does not recover this batch.
- `scheduler.c:916–927` sets per-CPU `g_deferred_active` before invoking reapers and clears it only on ordinary continuation completion. Killing that continuation can leave the guard set, suppressing subsequent deferred cleanup on that CPU. This guard predates the new context hook; the new hook inherits the limitation. Clearing it blindly from another task would permit overlapping cleanup while an old continuation still runs and is not a safe repair.

The bounded checkpoint therefore excludes task cancellation during retained reads and reclamation. Closing these blockers requires an owned cancellation/cleanup protocol that covers transient pins, detached retirement work and deferred-active ownership, with a proven stopped-task boundary and explicit handling of ISR acquisitions. Valid native controlled-interleaving success must not be described as cancellation or full SMP qualification.

Final diff scope review: diagnostic build flag defaults off, requires HEADLESS_AUDIT and rejects BENCH_MODE; init invokes the diagnostic only under that flag. The diagnostic tests empty contexts and replacement identity, not populated-region reclamation. Existing six bridge command entry points remain present; only APPLOAD functionality is intentionally unavailable. Header/internal registry visibility, core lookup conversions, task puts and full-width syscall validation match the stated scope. No additional accidental functional deletion was found after restoration. Eight focused host tests passed in 3.292 seconds (`/private/tmp/vos-ai-context-security-review-tests.log`), and `git diff --check` passed. This reviewer did not run native compilation or a guest for this checkpoint; their evidence belongs to the coordinator.

The preservation fixtures have no runtime Git dependency. All four external-caller tests also passed in a temporary source-only tree without `.git` (`/private/tmp/vos-ai-callers-no-git-tests.log`); committing the changes cannot alter their expected values.
