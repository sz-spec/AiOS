## Local hypothesis and acceptance conditions

The preserved health ELF is unchanged, but its producer calls GETTIME for every push-loop iteration. Counters should separate syscall entry/exit, handler time, signal checks, deferred work, CPU-ID queries, root synchronization, CR3 writes and actual reschedules. Prefer aggregated counters outside the measured loop; per-call logging would distort the workload. Compare identical instrumentation in old/current kernels with the same emulator, firmware, memory, workload order and isolated run conditions. Preserve failed samples and distinguish guest time from host elapsed time.

The **compare-before-store candidate was rejected and reverted** after its full-suite run reported 34,970 messages/s, below the unchanged 80,000 threshold. The health workload was unchanged. That individual failed sample does not identify a cause or establish statistical regression magnitude; no production optimization was accepted on its basis.

At the research/design stage, two separate bounded candidates were selected for evaluation; this section records their rationale:

- **Deferred empty-path acquire-load:** in `kernel/src/sched/scheduler.c`, observe the owning CPU's pending bit before acquiring the active guard. An observed zero returns without clearing anything, so a racing producer's publication remains for the next safe point. A nonzero observation retains the existing active guard and consuming exchange. Tests must cover publication immediately after a zero observation, publication during a drain, recursive entry, remote CPU ownership and IRQ-disabled callers. Existing no-live-migration and cancellation limitations remain. The intended saving is avoiding locked exchanges on empty safe points; it is not a bypass of pending cleanup.
- **Split-range root loops:** in `kernel/src/arch/x86_64/kpti_roots.c`, copy indices 0–256, zero 257–510, then copy 511. This preserves exactly 512 destination writes and 258 source reads, with the same desired values and increasing-index order in abstract C. It removes the upper-loop per-entry choice, not root synchronization. Null/overlap checks, AS lock, root binding, Accessed-bit copying, mapping revocation and CR3/flush behavior stay unchanged. Local GCC15 inspection is not production GCC16 evidence, and compiler lowering need not preserve an identical machine instruction sequence.

Qualify each independently against identical instrumentation and unchanged guest workload. Root-loop tests must compare arbitrary roots, mapping removal and permission changes, A-bit differences and rejected overlapping storage. Inspect production-generated code before attributing any improvement to branch or atomic-instruction reductions. Native isolation/translation regressions must remain effective. No unmeasured candidate is a demonstrated cause or remedy for the health failure.

**The 80,000 messages/s threshold, duration, messages and correctness checks remain unchanged.** Keep user MMIO denied, preserve ownership/refcount rules, user/kernel permissions, register isolation, root switching and TLB acknowledgement. Do not bypass signal delivery or resource cleanup for GETTIME. A narrower empty-work fast path needs synchronized state and a proof that pending work cannot be lost. No physical-hardware, full-SMP, cancellation-safety or release qualification follows from these discussions.

## Subsequent coordinator qualification

The combined changes subsequently passed all 57 programs in two BIOS and two UEFI runs with the unchanged health ELF (86,575; 90,635; 88,460; and 87,786 messages/s). Two clean builds produced byte-identical ISO/kernel/bootloader artifacts. See the [qualification report](health-performance-2026-09-17.md) and its preserved raw evidence. This bounded result does not establish one complete cause for all historical performance variation.
