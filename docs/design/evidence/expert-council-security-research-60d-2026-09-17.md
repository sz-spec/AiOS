## Repaired findings: do not revive stale negatives

The council's original four-CPU orphan adoption was repaired in `3ce56da`; creator-first SHM finalization in `3daf340`; immutable creator authorization and stale IDs in `9e582270`; deferred creator-exit cleanup in `8c23007`. Their linked matrices qualify specific contracts, not all IPC/SMP behavior. See [dated council dispositions](expert-council-2026-09-15/README.md).

The original ISO reproducibility failure (2,555 differing bytes) was narrowed to Limine build-ID inputs and ISO dates. The correction preserves GNU build IDs, strips unpublished intermediate debug input, normalizes private paths/dates and fingerprints target flags. Two final2 clean builds produced identical ISO `a0c99dc7e3aedf77e85c2e94cd128600fc40a87470b78a5aa352627901441472` and all eight compared artifacts; `/private/tmp/vos-final2-repro-20260917/result.json` records this. It is a bounded build result, not signed supply-chain or runtime proof. The product report's earlier absence of reproducibility evidence is superseded for this snapshot.

Final2 host verification passed **99 discovery tests**, six focused msgqueue/MMIO/repro tests, all native-build-check groups and diff checks. Inventory: `/private/tmp/vos-final2-host-20260917-inventory.json`. Host checks do not erase guest performance failures.

## Primary recent research and applicable fixes

These reports identify analogous mechanisms or engineering lessons, not CVEs assigned to vOS. Patch proposals are not assumed merged. The recommendations are council inferences.

- **2026-09-08 UTC** (header September 7, 20:29 -0700): [oss-security ZcopyReaper](https://www.openwall.com/lists/oss-security/2026/09/08/1). The researchers report Linux RDS zerocopy lifetime exploitation by an unprivileged local user; the message specifies affected configuration and a fixing commit. Apply the lesson to `ipc/msgqueue.c` and task reaping: pins, cancellation and last-access ordering require actual adversarial lifecycle tests. This is not evidence that vOS implements Linux RDS or shares the CVE.
- **2026-09-08**, revised **2026-09-15**: [Cisco UEFI shell advisory](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-ucs-uefi-sb-bypass-eb6xC5GW). [CERT/CC VU#718077](https://kb.cert.org/vuls/id/718077), published/revised **September 8**, describes embedded-shell raw memory access and boot-entry bypass. Include firmware and boot-variable permissions in the Secure Boot threat model; do not equate ISO signatures with complete platform trust. Some vendor statements embedded in the CERT note predate the window; they are not presented as new September disclosures.
- **2026-08-26–31**: [OSDev BAR5 discussion](https://forum.osdev.org/viewtopic.php?t=58312). The author's AHCI observations concern register offsets and mapped BAR size. Apply to driver layout/range assertions and discovery. It is a first-person debugging report, not a confirmed security advisory or proof that an arbitrary physical address is backed.
- **2026-08-31**: [LKML DLM usercopy whitelist patch](https://lists.openwall.net/linux-kernel/2026/08/31/2001). Original patch description scopes allowed copying to the intended object field. Apply object-boundary checks to syscall callers rather than weakening usercopy hardening. The message's automatic explanatory addendum is not relied upon.
- **2026-09-08**: [LKML encrypted DMA/IOMMU discussion](https://lists.openwall.net/linux-kernel/2026/09/08/1865). Distinguishes IOVA DMA masks from physical encryption attributes. Apply to NPU/VFIO address types and domain setup; the discussion does not establish vOS DMA containment.
- **2026-09-01**: [QEMU TCG dispatch-overhead series](https://patchew.org/QEMU/20260901034808.3524945-1-mattst88%40gmail.com/). The author's Alpha user-mode workload illustrates substantial dispatch/cache cost and separates instruction reductions from wall-clock gains. It is not a macOS/x86-system-mode benchmark. Profile before optimizing and retain workload/binary identity; no claimed cure for the 39K/97K observation follows.
- **2026-09-06/08**: [QEMU PMU deadline patch](https://www.mail-archive.com/qemu-devel%40nongnu.org/msg1223600.html) and [VM-elapsed clock review](https://www.mail-archive.com/qemu-devel%40nongnu.org/msg1224160.html). These RISC-V discussions distinguish host ticks, VM time, instructions and icount time warp. Use deterministic experiments for correctness separately from physical throughput; do not satisfy the existing 80K gate using synthetic guest seconds.
- **2026-09-15**, forum announcement **September 16**: [Qubes QSB-119](https://forum.qubes-os.org/t/qubes-users-qsb-119-potential-attacker-controlled-format-string-in-qvm-open-in-vm/43297). Error-path formatting and missing build hardening matter even within an isolated system. Audit untrusted names/log paths and actual build flags. The advisory explicitly does not establish a VM escape.

Primary oss-security/CERT/QEMU patch pages were opened and dates checked. Some LKML/Mail Archive pages yielded indexed original-message text but failed repeat direct opens; these are disclosed retrieval limits. No verified in-window primary source was found that attributes our slowdown specifically to macOS, BIOS versus UEFI, or a known QEMU regression. No out-of-window source is used to fabricate a recent finding.
