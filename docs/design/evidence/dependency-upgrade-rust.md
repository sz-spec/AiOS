# Desktop Rust dependency migration — 2026-09-13

Latest direct crate declarations and Cargo.lock supplied by the dependency update were compiled on aarch64-apple-darwin. Source migration uses rand 0.10.2 `Rng` / `rng()` and hmac 0.13.0 `KeyInit`; SHA-256 uses sha2 0.11.0. Tauri 2.11.5 generated ACL schemas were regenerated by its build script. Application capability/configuration files were not relaxed.

## Validation

`cargo test --locked` passed **108 tests**, with no ignored or failed tests: 76 unit, 4 supply-chain integrity, 6 mock Unix-socket VBus, 22 protocol conformance. Full log: `/private/tmp/vos5-rust-tests.log`. Socket tests require permission to bind temporary Unix sockets; the sandbox-only attempt failed with permission denied and the authorized rerun passed.

Invocation (from desktop/src-tauri):

```sh
env CARGO_HOME=/private/tmp/vos5-cargo RUSTUP_HOME=/private/tmp/vos5-rustup \
  TAURI_CONFIG='{"bundle":{"externalBin":[],"icon":[]}}' \
  /private/tmp/vos5-cargo/bin/cargo test --locked
```

The same temporary configuration is used for `cargo check --locked` (`/private/tmp/vos5-rust-check-final.log`). **These checks do not validate packaging.** An ordinary build correctly fails because `binaries/vos-backend-aarch64-apple-darwin` and configured icon assets are absent. No placeholder sidecar was created and no production configuration was changed. Release packaging must build and verify the real backend and provide real icons. Windows/Linux execution and signed application installation are untested.

## Security evidence and boundaries

- Added RFC 4231 case 1 HMAC-SHA256 and RFC 5869 case 1 first 32 output bytes known-answer tests, independent of sign/verify round trips.
- Added rejection tests for changes to every authenticated routing-prefix byte and for wrong keys. Existing payload/tag tamper and unsigned-frame rejection tests pass.
- The existing `subtle::ConstantTimeEq` comparison remains in the verification path. Tests verify functional rejection, not physical timing resistance.
- `rand::rng()` retains the upstream cryptographic ThreadRng, seeded from SysRng and periodically reseeded (upstream source documents ChaCha12 and 64 KiB reseeding). No deterministic or weaker RNG was substituted. ThreadRng does not automatically reseed after fork or guarantee memory zeroization; the API migration does not resolve these broader threat-model considerations.
- Updated memmap2 integrity pin to 0.9.11 only after independently retrieving the official [crates.io index](https://index.crates.io/me/mm/memmap2) and comparing the downloaded archive hash: `d1219ed1b7f229ee7104d281dd01d6802fe28bb6e95d292942c4daacdeb798c0`. This proves registry/archive consistency, not absence of vulnerabilities.
- Existing HMAC wire coverage remains `header[0..16] || payload`; trailing flags/reserved bytes are not cryptographically covered. Existing optional-HMAC negotiation and backend fallback behavior require separate security review. This update does not claim mandatory authenticated transport or production sidecar enforcement.
- Tauri's generated default permission definitions evolve with upstream (including supports-multiple-windows and tray icon metadata). Application grants were not edited; review inherited default capability changes before shipping.

No Git commit or publication was performed by this migration agent.
