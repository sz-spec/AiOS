# Authentication bcrypt migration — 2026-09-14

Scope: `backend/tools/auth.py`, focused offline tests. The minimal backend image could not import this module because it depended on Passlib, which was absent from the minimal profile. The full updated environment had bcrypt 5.0.0; a direct offline reproduction of Passlib 1.7.4 hashing a short synthetic password raised ValueError from its bcrypt backend self-test (72-byte input), alongside its missing `bcrypt.__about__` warning. Direct bcrypt avoids that incompatibility without downgrading the cryptographic library.

Replaced CryptContext usage with direct maintained bcrypt APIs. Public `hash_password` / `verify_password` names and successful return types remain unchanged. New hashes use independent random salts and cost 12, matching the previous default. Existing bcrypt formats `$2a$`, `$2b$`, `$2y$` remain supported. The test fixture was independently calculated with Passlib 1.7.4's pure-Python `raw_bcrypt`, so the compatibility assertion is not only a new-library round trip.

The password boundary is explicitly **72 UTF-8 bytes**, not 72 characters. Longer values are rejected, never silently truncated or prehashed. NUL remains rejected as with Passlib; invalid UTF-8 strings are rejected. Hashing invalid input raises ValueError, verification returns False for invalid input or malformed stored hashes, and invalid password updates return False without replacing the previous hash. Pydantic creation/login models enforce the same boundary; an in-process FastAPI test verifies an oversized request receives 422 before reaching its handler.

This policy intentionally does not reproduce historical silent truncation of passwords longer than 72 bytes. Accounts originally created with such passwords require an explicit password-reset/migration policy; accepting suffix-insensitive passwords is not claimed as compatibility.

JWT generation, token semantics, roles and storage behavior were otherwise left unchanged. The module still has its preexisting in-memory store and ephemeral-key development fallback. No passwords, hashes from real accounts, or generated JWT secret values were logged. Tests use synthetic fixtures and make no external requests.

The coordinator added direct `bcrypt==5.0.0` and `email-validator==2.3.0` to all four Python profiles and removed Passlib from the declarations/updated environment. Testing also exposed missing `email-validator` for the existing Pydantic EmailStr models; this is a real direct dependency, not removed validation. An offline-only install attempt failed because it was not in cache; the coordinator subsequently resolved and installed it.

Validation command: `.venv-upgrade/bin/python backend/tests/test_auth_bcrypt_migration.py`. Seven focused cases cover legacy hash variants/wrong password, salt/cost/round trip, Unicode byte boundary and NUL, malformed hashes, model validation, HTTP 422 and store mutation boundaries. **All 7 tests passed in 2.159 seconds** in the actual synchronized `.venv-upgrade` environment. Log: `/private/tmp/vos5-bcrypt-migration-tests.log`. Python source compilation passed. The existing development warning states only that the JWT key is ephemeral; no key value is printed.
