# SHM creator-exit cleanup: independent design review

Reviewer `/root/mcp_upgrade`; initial source `3cccbc9`; 2026-09-15. Source inspection only at this point. No implementation or native completion is implied.

Creator ownership currently survives task death unless explicitly closed. Exit paths disable interrupts and cannot safely run the region finalizer inline: mapping teardown, PMM work and mutex destruction belong in deferred process context.

Recommended bounded design: an IRQ-safe mark operation scans the bounded SHM registry by the immutable, nonzero creator cookie and records pending creator release. Retain the creator reference until a deferred drain claims it. Per-region pending state avoids allocating queue nodes during exit, retaining dead task pointers or resolving reused PIDs. Public creator close, repeated death marks and drain must share a unique creator-release claim; no sequence may decrement creator ownership twice. A pending reference keeps its slot/generation alive until the drain acts. Verify full handle identity when using a snapshot, or claim the still-live registry entry under lock. Physical finalization remains outside registry/region locks with interrupts enabled.

Creator release can precede address-space release because mappings independently retain backing. The operation must be idempotent after explicit close, after prior marking and after finalization/reuse. No caller-controlled cookie should enter a public cleanup syscall. Missing-current/zero creator handling must remain fail-closed rather than granting a cleanup bypass. Decide explicitly whether public new maps remain permitted after creator death; existing creator-close semantics allow retained mappings, which is distinct from creator destruction authority.

Coverage must include normal exit, user fault death, task kill and quota termination. Current direct ZOMBIE transitions exist in `interrupts.c`, `task.c` and a vbus child path, so a hook only in `vos3_task_exit` is insufficient. Reap/direct-destroy fallbacks help but cannot be the only cleanup trigger: an uncollected zombie must not retain creator resources indefinitely. Remote kill versus concurrent creation is a separate synchronization boundary and must not be assumed solved by an ID scan.

Required native controls: creator exits without explicit close while a foreign public mapper survives and verifies contents; final mapper cleanup releases the region; creator with no mappings exits and registry/backing reclaim without requiring wait; explicit-close-then-exit does not double-release; repeated marking is harmless; faulting creator receives the same cleanup; a reused slot survives any stale pending work. Prove deferred execution and owner-independent identity with actual markers and accounting rather than wait completion alone. Preserve prior authorization, stale-handle and creator-first tests.
