# Native capability failures: scoped implementation plan

The failing tests in `test_finetune_rigor.py` and `test_vmm_security.py` remain enabled. They expose missing integrations; adding unused names is not an acceptable fix. A scan of the expected mmr_audit.c/tpm2.c/dispatcher.c locations across all eleven donors found no `mmr_record_finetune_step`, `vos3_tpm_seal_adapter`, or `task_steering_logic` implementation. These are contracts ahead of implementation, not a located implementation that can simply be copied.

1. **Training audit contract.** Current MMR leaf has timestamp, syscall_nr, entropy[8], data[32] and a real mmr_append primitive. Implement a checked 4×u64 little-endian event codec with tool ID0x2000 and a real caller. The hosted engine currently emits `MMR_FINETUNE_STEP` through VBus: command routing, authorization, numeric representation and error acknowledgment must be wired and tested, not just an isolated append function. Test actual extracted codec on asymmetric byte patterns/zero/max, verify exact appended leaf and failure paths, then native command integration. Entropy unavailability must have explicit failure semantics; don't invent hardware entropy.
2. **TPM adapter contract.** Current tpm2 lacks PCR11 adapter API. Design a checked SHA256 digest/PCR11 extension operation and truthful response; PCR extension is measurement, not TPM sealed-object confidentiality or proof that a model is trustworthy. The test's required `VOS-CERTIFIED-SOVEREIGN` log should not become a false security claim. Existing TPM command path needs real/simulator integration, offline/error rejection, known digest checks, and no success merely because a log line was emitted. Wire hosted `TPM_SEAL_ADAPTER` only after command authentication and result semantics are specified.
3. **Slot quarantine and dispatch.** slot_state.c exists but is not compiled; its current-slot ID is one global and the registry/state/zone arrays are unsynchronized. Its scrub loop dereferences a registered base/length directly. Do not connect that handler to generic mprotect rejection on SMP without task-bound authoritative slot ownership, valid range/lifetime ownership, state-transition synchronization, and safe deferred scrub. A wrong slot on another CPU must not be quarantined. Current generic VMM W+X denial remains active; the absent feature is attributed slot quarantine/audit, not absence of W^X rejection.
4. **NPU/VFIO source wiring.** npu_ops.c and vfio_core.c are retained but not built. NPU code documents no real vendor DMA/IOMMU offload. Compile/link their dependency graph in an isolated target first; then test capability denial, terminal slot denial, overflow/size checks, failed mapping rollback and ownership. Actual callers/driver registration and hardware evidence are separate required gates. Do not satisfy Makefile text tests while linker garbage collection leaves an unused scaffold.
5. **PUD constant.** Canonical VMM already defines VOS3_PAGE_SIZE_1G. The absent VOS3_PUD_SIZE alias alone is a naming compatibility issue, not evidence 1GiB support is missing. Before adding an alias or updating the test, tie it to an actual consumer and compile-time numeric equality test; avoid claiming dynamic hugepage behavior from a constant.

The newly tested PRO wrapper retains the CORE engine by design; its old relocation-only tests contradicted the reconstructed implementation. It now imports correctly in both package layouts and takes an explicit FineTuneConfig. Behavioral tests preserve license denial and check real constructor/config forwarding plus train delegation. The gate remains an environment-based scaffold, not cryptographic licensing.
